# Test-case catalogue — Element Web + theme-loader + mobile-themes

Generated by `python3 tests/catalogue.py` (edit the cases there, not here). Machine-readable copy: `tests/catalogue.json`. Automation: `tests/harness/functional.mjs` and `tests/harness/viewports.mjs` (results in `tests/reports/matrix/`).

Scope: Element Web 1.12.33 on element.datanauten.de and the loader dev server, with the theme loader (72 themes in 10 families), the mobile-themes module (`mobile/dist`, injected by request interception) and, on production, the 15 other datanauten modules. Regions follow `docs/CONTRACT.md` §4; edge-case sources: `research/01-theme-system.md` §6, `docs/MOBILE-ISSUES.md`, `docs/PROD-QA.md`.

**Priorities.** P0 = breaks core use (can't load, read, send, navigate or switch back) · P1 = a major feature or region broken · P2 = degraded · P3 = cosmetic or rare.  
**Applies.** `all` = all 72 themes + Element default · `sample` = the 12-theme sample below · `mobile` = mobile-themes at phone/tablet sizes · `default` = Element default only · `prod` = production only.  
**Auto.** yes = fully scripted · partly = scripted capture, human judgement · manual = needs a second user/device or real hardware.  
**Readability rule.** Variants with stage `level-5`+ or ids/descriptions marked invisible/unreadable are *report-only* for readability checks (TL-01, RL-01, A11Y-08) — but THM-02/03/04 (way back) are hard P0 for them too (contract §7 `.tl-ui`).
