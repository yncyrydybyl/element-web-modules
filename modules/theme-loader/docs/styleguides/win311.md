# Windows 3.11 — style guide (`win311`)

Data twin: `docs/styleguides/win311.json`. Manifest: `themes/win311/themes.json`. Assets and licences: `themes/win311/README.md`.
Reference captures: `docs/styleguides/refs/win311/`:
- `pcjs-win31-windows-default.png`: Windows 3.10 booted in PCjs, 640×480 shown at 2×
- crops of the title bar at 4×
- `CONTROL.INI-win31-color-schemes.txt`: the retail scheme table

## 1. Concept

Element becomes **Windows for Workgroups 3.11**:
- The whole client is **one Program Manager application window**.
- Its AppWorkspace holds **MDI child windows**: "Rooms" (room list), the room itself, and the right panel (Members / Room Info / Threads).
- **Spaces are minimized program-group icons** along the bottom of the workspace.
- Every window has the iconic 3.1 chrome:
  - a flat navy title bar with a centred bold title
  - a control-menu box on the left
  - ▼ ▲ triangle buttons on the right
  - **no close button**

The family is about the jump from authenticity to fun:
- The pure variants use the **exact shipped colour schemes** and the VGA bevel grammar.
- The other stages bend these for chat ergonomics or for hype.

### Stage axis

```
seriousness ↑
 8 │ win311-usable (usable)      win311-default (pure)
 7 │                             win311-leather (pure, dark)   win311-daylight (pure, clock)
 6 │                                              win311-2030 (future)
 3 │                                                            win311-cyberpunk (cyberpunk)
 2 │                                                            win311-hotdog (exciting)
   └──────────────────────────────────────────────────────────────────────── hype →
        3                4                5             7                    9
```

- **pure ↔ usable:**
  - default / leather / daylight are faithful: the W95FA pixel font at its native 12.5px (= MS Sans Serif 8pt), compact density, flat 1px edit fields, the fixed-size scroll thumb, no hover.
  - usable keeps the chrome but brings back:
    - hover states
    - CTL3D sunken fields
    - proportional scrollbars
    - roomy rows
    - AA contrast
    - all of Element's affordances
- **past ↔ future:** 1992 schemes against the 2030 edition, where Windows 3.x never died. It keeps the same grammar and adds high-DPI type, frosted title bars, soft shadows and a dock of program groups.
- **seriousness ↔ hype:**
  - Hot Dog Stand shipped exactly like this, and it is the joke.
  - Cyberpunk takes it to 16-colour VGA neon with a DOS prompt.

### 2.1 Colour schemes

| Source | What it gives us |
|---|---|
| **CONTROL.INI** | The retail Windows 3.1 `CONTROL.INI [color schemes]` is copied verbatim in `refs/win311/` from `joncampbell123/win31igdrv`. It is identical to the table in MS KB 102976. | **PCjs pixel-sampling** | I booted Windows 3.10 in PCjs (VGA) and pixel-sampled it to verify Windows Default. The PCjs display shows the VGA DAC's 6-bit levels: grey `#C0C4C8` for `#C0C0C0` and navy `#0000A8` for `#000080`. We use the logical values. These match the dossier's column. |
| **NT 3.1 registry defaults** | KB 102976 differs from Windows 3.1: InactiveTitle `#C0C0C0` and Background `#FFFFFF`. Don't mix them up. |

### 2.2 Chrome

These come from the `VGA.DRV` OBM_* bitmaps (libwinui, Tier 1). The PCjs crops confirm them.

| Element | How it is drawn |
|---|---|
| Bevel | Not symmetric: 1px black frame, **1px** white top/left, **2px** `#808080` bottom/right. Pressed: a single 1px grey top/left edge, glyph +1,+1. A symmetric bevel reads as Windows 95. |
| Caption buttons | 19×18 |
| Control-menu box | 18×18, from a 36×18 strip. It shows a long white bar with a black outline and grey shadow on the application window, and a short bar on MDI children. |
| Scroll arrows | 17×17, with a stemmed arrow (7×4 head on a 3×3 stem). The thumb is fixed size. |
| Window frame | Flat. Outer 1px black, a `BorderWidth` 3 × ActiveBorder band, inner 1px black, with resize notches. |
| Modal dialog | 1px black plus a thicker inner border in the title colour. No sizing band. |
| Push button | A round-cornered rectangle: 1px corner cut, 2px on the heavy default ring. 23px high (14 DU). The standard width is 75px. |
| Check box | An **X**, not a tick. The menu check mark is a tick. |
| Menus | No shadow. No hover anywhere in the era. |

| Dialogs | MS Sans Serif 8pt | 13px cell |

From the PCjs capture:
- The menu reads **File Options Window Help**, with underlined mnemonics and white text.
- Group windows have white clients.

## 3. Shared design system (all variants)

### Typography

| Role | Pure / usable | 2030 | Cyberpunk |
|---|---|---|---|
| UI text | `local("MS Sans Serif"), "W95FA"` 12.5px (pure; native size, 80 font units = 1px) / 16px (usable) | `"Pixelify Sans"` 15–16px | `"PxPlus IBM VGA 8x16"` 16px |
| Title bars, menu bar, icon labels | "W95FA" **700** = *W95FA Overstrike Bold* (our OFL derivative: glyph OR-ed with itself shifted 1px, the GDI way), centred | Pixelify Sans 700 | PxPlus, upper case |
| Code / DOS | `local("Fixedsys"), "PxPlus IBM VGA 8x16"` 16px | same | same |

Set these on `--cpd-font-family-sans/mono`, with `!important`, on `html[data-tl-family="win311"]` and `[class*="cpd-theme-"]`.

| Rule | Detail |
|---|---|
| Smoothing | `-webkit-font-smoothing: none; font-smooth: never` |
| Sizes | Pure: everything 12.5px (crisp 1:1 pixels), code 16px PxPlus. Usable: 16px. The heading scale collapses to one bold size, because Windows 3.1 had no type scale. |
| Mnemonics | Menu-bar items render the first letter underlined (`::first-letter { text-decoration: underline }`). |

### Geometry

- `--cpd-avatar-radius: 0` (square avatars, 1px black frame) and all radii 0.
- Push buttons get the corner cut via `border-radius: 2px` on a 1px black border, which knocks out the corner pixel.
- The bevel is a `box-shadow` stack:

  ```css
  inset 1px 1px #FFF,           /* highlight */
  inset -1px -1px #808080,
  inset -2px -2px #808080       /* 2px shadow */
  ```

  The 1px black frame is a `border`.

### Colour roles → Compound tokens

The mapping is in `themes.json` `tokens`. Phase B extends it to the ~40 tokens in research/01 §2.3.

| Scheme slot | Token(s) |
|---|---|
| Window | `--cpd-color-bg-canvas-default` (timeline, dialogs) |
| AppWorkspace | `.mx_MatrixChat` background, the gaps between MDI windows |
| Desktop | `html` / `body` background, outside the app frame |
| ActiveTitle / Hilight | `--cpd-color-bg-action-primary-rest`, `--cpd-color-bg-accent-rest`, `bg-action-tertiary-selected`, selection |
| ButtonFace / Shadow / Hilight | `--cpd-color-bg-action-secondary-rest`, plus the `--w-face`, `--w-shadow`, `--w-hi` family vars in `shared.css` |
| GrayText | `--cpd-color-text-secondary` (pure); usable uses `#595959` for AA |
| WindowFrame | `--cpd-color-border-interactive-primary`, `--cpd-color-separator-*` |
| Decorative 1–6 (names, default avatars) | The 16-colour VGA set:<br>- light variants: `#800000 #008000 #808000 #000080 #800080 #008080`<br>- dark variants: `#FF0000 #00FF00 #FFFF00 #00FFFF #FF00FF #C0C0C0` |

`shared.css` exposes one set of family variables per variant:

```
--w-desktop --w-workspace --w-window --w-text --w-menu --w-menutext
--w-title --w-title-inactive --w-titletext --w-titletext-inactive
--w-border --w-border-inactive --w-frame --w-scrollbar
--w-face --w-shadow --w-hi --w-btntext --w-graytext --w-hilight --w-hilighttext
```

The variant files only fill these in, so the 21 slots map 1:1 to the scheme table. Adding another scheme later (Arizona, Rugby…) takes about 25 lines.

└──────────────────────────────────────────────────────────────────────────┘

**Implementation notes:**
- **Spaces strip:** `.mx_SpacePanel` becomes the bottom row of the grid, with `flex-direction: row`. Nested space trees are hidden (`.mx_SpaceTreeLevel .mx_SpaceTreeLevel { display: none }`). The expand toggles are hidden. `.mx_QuickSettingsButton` moves to the end as a "Control Panel" icon.
- **Room items:**
  - Each room is a 32px avatar or `icon-room.svg` in a 1px frame, followed by the label.
  - Only the label is highlighted when selected, like Program Manager.
  - Unread rooms show "(n)" in bold. A mention shows a navy box.
- **Filters:** the room-list header and primary filters become a strip of small push buttons, like File Manager's drive bar.

**Timeline:**
- IRC-like group layout: bold name, timestamp `[hh:mm]`.
- The bubble layout falls back to square white boxes with a 1px black border.
- A highlighted (mention) row is inverted to navy/white.

## 6. Signature moves

1. The **title bar trio**: control-menu box (long bar or short bar), centred bold title on a flat colour, and the ▼ ▲ buttons. **No ✕.**
2. **Asymmetric bevel** (1px white, 2px grey) with black outlines everywhere, and push buttons with the cut corner pixel.
3. **Program Manager metaphor**: an application window with MDI children, spaces as minimized group icons, rooms as program items. Only the label is highlighted when selected.
4. **Aliased pixel type**, with System-bold titles and menus. Menu bars underline their mnemonics.
5. **Real scheme colours**, verified. A scheme can be swapped in about 25 lines because the 21 slots are variables.

## 7. Iconography

Our own pixel SVGs (`themes/win311/assets/`, CC0, generated by `tools/make-assets.py`):
- caption buttons
- scroll arrows and thumb
- control boxes
- check and option glyphs
- group, room and DM icons
- hourglass
- dithers and desktop patterns

Compound icons:
- Recoloured to `--w-text` and kept at 16px with crisp edges.
- In pure variants the most visible ones are swapped through CSS masks keyed on aria-label or class:
  - spaces home → group icon
  - spinner → hourglass
  - room avatar fallback → `icon-room`
  - DM → `icon-dm`
- Avatars:
  - light variants: `image-rendering: pixelated`
  - cyberpunk: CSS `contrast()` / `saturate()` posterise approximation

No real Microsoft icon bitmaps are bundled. They are copyrighted art, and our redraws keep the licensing clean.

## 8. Motion

The era has none: controls repaint, they do not animate.
- **Pure variants:** `--transition-*: 0s`.
- **Usable:** 100ms hover only.
- **2030 and cyberpunk:** animated, as described in §4.6 and §4.7.
- **Reduced motion:** `prefers-reduced-motion: reduce` disables every animation, including the blink, glitch, shimmer and wobble.
- **Spinners:** replaced by the hourglass bitmap, which does not rotate.

## 9. Accessibility stance

- **Focus:** always visible. The era's dotted rectangle is used, and in usable it gets an extra ring.
- **Pure contrast:**
  - Title and body text are 13–16:1.
  - GrayText `#808080` on white is 3.95:1. It is used only for timestamps and secondary metadata, which is authentic.
  - Usable raises it to `#595959` (7:1).
- **Hot Dog Stand:** white on red is 4.0:1. That is below AA for small text, and the description says so. The stage "exciting" makes it opt-in.
- **Daylight dusk:** title text is forced white, a documented deviation from the scheme.
- **Pixel fonts:**
  - Pure uses the native 12.5px (the original MS Sans Serif 8pt size; crisp pixels). That is small: usable uses 16px.
  - Usable follows the user font-size slider.
  - Browser zoom scales the pixel grid cleanly at 200%.
- **Hover:** usable adds hover for discoverability, even though Windows 3.1 had none.

## 10. What can't be themed → workaround

| Problem | Workaround |
|---|---|
| Iframes (calls, widgets) only take light/dark | Frame them as MDI children named "Video Call" / "Widget". |
| The virtualised room list can't wrap into an icon grid | One column of program items. The real icon grid goes to spaces. |
| No window management | Decorative ▼▲ buttons. The enhancer can map ▼ to collapse the left or right panel, ▲ to maximise the room (hide side panels), and the control box to the room options menu. |
| Bitmap .FON fonts are unusable on the web | W95FA (+ overstrike bold) / PxPlus. They blur at non-integer DPR, which we accept. |
| Twemoji and photos in full colour | Pure variants leave them alone (WinChat would have shown them anyway in 1993 as bitmaps). Cyberpunk posterises photos via CSS filter, but only on avatars. |
| Radix tooltips and menus have hashed classes | Style via `[role=tooltip]`, `[role=menu]` and `[data-radix-popper-content-wrapper]`. |
| Hard-coded colours (image view, toasts, devtools) | Per-selector overrides in `shared.css`. |

## 11. Enhancer plan (`themes/win311/enhance.ts`, shared by all variants)

1. **App frame:** `ctx.root` draws the outer Program Manager frame, the app title bar `Element – [<room name>]` and the menu bar.
   - Menu bar items: File (Settings, Sign out), Options (theme quick-switch), Window (cascade = toggle right panel), Help (About).
   - Each menu opens a Win 3.1 dropdown. Mnemonics work with Alt+letter.
2. **MDI title bars:** sibling overlays positioned over `.mx_LeftPanel`, `.mx_RoomView` and `.mx_RightPanel`.
   - Tracked with a ResizeObserver, never by moving React nodes.
   - The active window follows `document.activeElement`. Inactive windows get the InactiveTitle colours.
3. **Button wiring:**
   - ▼ / ▲ map to collapse / maximise via the existing Element UI buttons (programmatic click).
   - The control box opens the room context menu.
   - A double-click on the control box opens the "Leave room" dialog, an homage to close-by-double-click.
4. **Variant extras:**
   - daylight: Clock icon
   - cyberpunk: scanline overlay, DOS prompt prefix, glitch timer
   - 2030: desktop glow and the unread shimmer
5. **Cleanup and fallback:**
   - `unmount()` removes everything and disconnects all observers.
   - If anything fails, the CSS-only fallback (title bars as `::before` on panels) still looks right.
